## Goal

GitHub Actions runs the repo gate (fmt, clippy with warnings denied, tests, and the 80 % line
coverage floor) on every push to any branch and on every pull request, as fast as the work allows
by running independent checks in parallel. A single aggregate check is required on `main` by a
repository ruleset with no bypass, so nothing reaches `main` without passing it. A deliberately
broken pull request proves that the check goes red for a clippy warning and for a coverage drop,
that the merge is blocked, and that the fix turns it green. Story:
[ARIA-140](https://firephoenixgames.atlassian.net/browse/ARIA-140); subtasks ARIA-142, ARIA-144,
ARIA-146, ARIA-148.

## Non-goals

- Building or publishing images. `images.yml` (ARIA-123) owns that and is not touched.
- Deploying anything.
- Removing or weakening the local pre-commit hook. It stays; CI mirrors it.
- Changing the gate itself (the commands, or the 80 % floor).
- Running the test suite on Windows or macOS. The Windows job only compiles.
- Coverage reporting services, badges or PR coverage comments.

## Constraints

- GitHub Actions on GitHub-hosted runners (D13). The repo is public, so minutes and parallel jobs
  are free, but the Actions cache is capped per repository and shared with `images.yml`'s
  BuildKit cache.
- The gate is defined by `.githooks/pre-commit` and `docs/05-conventions.md`. CI must enforce the
  same commands with the same flags, at the same floor.
- protoc is vendored (`protoc-bin-vendored`), so no job needs system packages. The toolchain is
  pinned by `rust-toolchain.toml` (stable, with rustfmt and clippy).
- Actions are pinned by full commit SHA with the version in a trailing comment, and permissions
  default to none with each job asking for what it needs, matching `images.yml`.
- GitHub only offers a check as "required" after it has reported at least once, so the ruleset
  can only be created after the workflow has run.

## Decisions

- **The hook stays; CI mirrors it, and both change together.** Jann's call. Every check in
  `.githooks/pre-commit` has a counterpart in `ci.yml`, and a change to the gate changes both
  files in the same commit. Recorded as a rule in `docs/05-conventions.md` and as a pointer
  comment at the top of both files. Two deliberate differences are part of the rule, so nobody
  "fixes" them: CI has no separate plain test run, because the coverage job runs the suite and
  fails on a failing test; and CI may add platform-only checks the hook cannot run (the Windows
  compile). Rejected: deleting the hook and making CI the only gate (loses the per-commit floor
  and the fast local feedback); having CI call the hook script, alone or per stage (one source of
  truth, but couples CI's job layout to a shell script and was not wanted).

- **Parallel jobs, one per independent check, plus an aggregate.** fmt, clippy, coverage and the
  Windows compile run as separate jobs at the same time. fmt needs no build and reports in
  seconds, so the cheapest failure arrives first. Clippy builds in check mode and coverage builds
  instrumented, so they share nothing worth sequencing. Rejected: one job running the stages in
  order (wall time is the sum, and the first failure hides the rest); separate test and coverage
  jobs (a second full build for no extra signal).

- **No separate plain test run in CI.** The coverage run executes the whole suite, and a failing
  test fails it. Running the tests twice would roughly double the slowest job. The hook keeps its
  plain test step, which is the documented difference above.

- **One aggregate `gate` check is what `main` requires.** It depends on every other job and fails
  if any of them failed, was cancelled or was skipped. Branch protection names one stable check,
  so jobs can be added, split or renamed without touching the ruleset. Rejected: requiring each
  job by name (every layout change becomes a settings change, and a renamed job silently stops
  being required).

- **Triggers: `push` on every branch, plus `pull_request`.** This is the closest replacement for
  local feedback on branches with no PR open, and it matches the story's "every push and PR".
  Cost: a PR branch runs twice per push. That is free on a public repo. Concurrency groups are
  keyed by event and ref, so the two runs never cancel each other, and a newer push cancels the
  older run of the same event. Runs on `main` are never cancelled. Rejected: `pull_request` plus
  `push` to `main` only (a branch gets no checks until a PR exists).

- **Prebuilt tool binaries, not `cargo install`.** `cargo-llvm-cov` is installed as a released
  binary, which takes seconds rather than minutes of compiling on every run.

- **Separate cache per job.** Clippy's check-mode artifacts, the instrumented coverage build and
  the Windows target do not overlap usefully. A shared key would have each job overwrite the
  others' entries. Caches are saved only from `main`, so PR runs restore but do not churn the
  repository's cache quota, which `images.yml` also uses. Rejected: no target-directory cache
  (every run rebuilds the dependency tree, the bulk of the time); a single shared cache (thrash).

- **A Windows compile-only job.** Carried over from the aria-131 Deviations: agent-core's shutdown
  signal has a Windows branch that has never been compiled anywhere. A `cargo check` of the
  workspace on a Windows runner closes that gap cheaply. It is part of `gate`, so a Windows
  compile break blocks merge. Rejected: running the full suite on Windows (slow, and no Windows
  behaviour is promised yet); cross-checking from Linux with a Windows target (avoids a slow
  runner but needs the target's C toolchain for dependencies with build scripts, so it is less
  reliable than the real thing).

- **A repository ruleset on `main`, not classic branch protection, with no bypass.** Jann's call.
  It requires a pull request and a passing `gate`, and applies to admins too, so the acceptance
  criterion "`main` cannot be merged into without the check passing" holds literally. The ruleset
  JSON is committed to the repo so the setting is reviewable, and it is applied with `gh api`
  only after Jann approves the exact body. Cost: if CI itself breaks, the ruleset has to be
  edited to land the fix. Rejected: allowing admin bypass (the only admin could merge red);
  classic branch protection (older mechanism, not exportable as a file).

- **Order: workflow → caching → ruleset → proof.** The ruleset needs `gate` to have reported
  once, and the red/green proof runs last so it can also show the merge blocked.

## Open questions

None. Whether the Windows compile passes first time is a risk, not a question (see below).

## Risks

- **Coverage measured on Linux differs from local macOS.** Platform-specific code paths count
  differently. If the workspace sits near 80 %, the first CI run may fail a floor that passes
  locally. Signal: the first coverage job fails with no code change. Response: report the gap
  and decide with Jann, rather than lowering the floor.
- **The Windows compile fails.** It has never been compiled, so it may surface real errors in
  agent-core's shutdown code or in a dependency. Signal: the first Windows job is red. Response:
  a one- or two-line fix goes in C3; anything larger gets its own story, and the job is held back
  from `gate` until it lands (recorded as a deviation).
- **Cache quota pressure.** The repository cache is shared with `images.yml`'s BuildKit cache.
  Eviction would make every run cold. Signal: cache restore misses on consecutive `main` runs.
- **A no-bypass ruleset locks out a CI fix.** Accepted with the decision above. Signal: a red
  `gate` on a PR whose only change is to CI.
- **Duplicate runs on PR branches.** Doubled noise in the checks list. Accepted.

## Components

All components are `chore`. They are workflow, settings and documentation, with no Rust API to
design. Each is proven by observable CI behaviour, not by unit tests.

### C1 — Gate workflow (ARIA-142)

kind: chore
status: in-progress

**Responsibility.** A new workflow, separate from `images.yml`, that enforces the hook's gate in
CI as parallel jobs and reports one aggregate result.

**Contracts.** It runs on a push to any branch and on every pull request. fmt, clippy and coverage
run as independent jobs with the hook's exact commands, flags and 80 % line floor. The aggregate
check fails if any job it depends on failed, was cancelled or was skipped, and passes only when
all succeeded. Superseded runs of the same event and ref are cancelled, except on `main`. Actions
are pinned by SHA, and jobs get only the permissions they need. The top of the file points to the
hook and states the mirror rule.

**Tests.** A push to the plan branch triggers the run, and every job appears in the checks list.
The first run on the current tree is green. A second push while a run is in progress cancels the
older run. Opening the PR adds a pull-request run alongside the push run, and neither cancels the
other.

**Done when.** The workflow is green on the branch for both a push and a pull request, and the
aggregate check is visible under its stable name.

### C2 — Cargo caching (ARIA-144)

kind: chore
status: in-progress
depends-on: 1

**Responsibility.** Restore the cargo registry, git dependencies and build directory per job, so
a warm run rebuilds only the workspace crates.

**Contracts.** Each job has its own cache, keyed on the toolchain, the lockfile and the job, so
jobs never overwrite each other's entries. A change to `Cargo.lock` or the toolchain invalidates
the cache. Caches are saved from `main` and restored everywhere. Caching never changes whether a
job passes.

**Tests.** A run after a warm cache shows a restore hit in every job. Its wall time is measurably
below the cold run, and both timings are recorded in the PR. A lockfile change produces a miss
and then a fresh save on `main`.

**Done when.** Cold and warm timings are recorded, and warm runs restore in every job.

### C3 — Windows compile check (from PR #5)

kind: chore
status: in-progress
depends-on: 1

**Responsibility.** Compile the workspace on a Windows runner, so agent-core's Windows shutdown
branch is built somewhere.

**Contracts.** The workspace compiles on Windows, including the Windows-only shutdown code. The
job is part of the aggregate check. It only compiles; no tests run.

**Tests.** The job is green on the current tree. A deliberately broken line inside the
Windows-only branch turns it red while the Linux jobs stay green. Do this on a scratch commit
that is never merged; it proves the code really is compiled.

**Done when.** The job is green, and the scratch proof has been seen red.

### C4 — Required check on `main` (ARIA-148)

kind: chore
status: pending
depends-on: 1

**Responsibility.** A repository ruleset on `main` that requires a pull request and a passing
aggregate check, with no bypass. Its definition is committed to the repo.

**Contracts.** Nothing lands on `main` except through a pull request whose aggregate check
passed. This applies to admins. A direct push to `main` is refused. The committed definition
matches what is live on GitHub. It is applied only after Jann approves the exact body.

**Tests.** The live ruleset, read back from the API, matches the committed file. A direct push to
`main` is refused. Try this with a harmless no-op, and only if Jann agrees to the attempt. A PR
with the check still running cannot be merged.

**Done when.** The ruleset is live, matches the repo copy, and a refused push or blocked merge has
been observed.

### C5 — Red/green proof (ARIA-146)

kind: chore
status: pending
depends-on: 2, 3, 4

**Responsibility.** Demonstrate the three acceptance criteria on a throwaway pull request, and
link the evidence from the story.

**Contracts.** The proof PR is never merged and its branch is deleted afterwards. Each red is
caused by exactly one deliberate change, so the cause is unambiguous.

**Tests.** A commit adding a clippy warning turns clippy and the aggregate check red, and the
merge is blocked. Reverting it turns them green. A commit that adds enough untested code to push
line coverage under 80 % turns coverage and the aggregate red, and the merge is blocked.
Reverting it turns them green.

**Done when.** The PR shows the red, green, red, green sequence. Its link is in an ARIA-140
comment covering all three criteria, and the PR is closed unmerged.

### C6 — Conventions: CI enforcement and the mirror rule

kind: chore
status: pending

**Responsibility.** Bring `docs/05-conventions.md` up to date: the gate is now enforced in CI as

**Contracts.** The line saying the hook is the only enforcement until a gate workflow exists is

**Tests.** A reader can find, from the conventions page alone, both files that define the gate,

**Done when.** The page is updated and consistent with the files on the branch.

### C7 — Reliable tracing capture in agent-core tests (found by C1)

kind: bugfix
status: done

**Responsibility.** Make the tests that capture tracing with a thread-scoped subscriber see every
event, regardless of what other tests run in parallel.

**Contracts.** A test's capture sees the events its own server emits even when tests run on
several threads. Tests that assert *no* events can fail again, which a poisoned interest cache
made impossible.

**Tests.** The regression check is the reproduction: the `decide` and `health` binaries under
`--test-threads=2`, 30 runs each. Before: 28/30 failures in `decide`. After: 0/30 in both.

**Done when.** The reproduction is clean and the CI coverage job is green.

## Deviations

- C1, C2 and C3 landed in one commit: all three live in `ci.yml`, and the cache and Windows
  job are a handful of lines each. Claude wrote the chores at Jann's request, not Jann.
- C7 added: the first CI run failed a test that passes on Jann's machine.
  `backend_failure_emits_an_error_level_log_record_carrying_the_session_id` lost its ERROR record
  because tracing-core (0.1.36) caches callsite interest from whichever thread registers a
  callsite first while only one dispatcher is live. A parallel subscriber-less test cached
  `never`. Fixed by a permanent global no-op dispatcher in a shared test helper. Claude wrote it
  at Jann's request. Rejected: a separate test binary for the logging test (one more test there
  and it returns), and single-threaded tests in CI (slower, and it hides the bug).
